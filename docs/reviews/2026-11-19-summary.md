# Review, 19 November 2026: summary

Three independent reviews of SpartanReferee after the learning platform and the referee pages were built: [UI](2026-11-19-ui.md), [code](2026-11-19-code.md) and [production readiness](2026-11-19-production.md). Each was done by a separate reviewer reading the code and screenshots afresh; the High findings below were checked against the code before being listed.

**Verdict**: the code is careful (permissions checked on the server, every query parameterised, untrusted text escaped, changes audited, published content versioned), and it works as a demonstration. It is **not ready for a pilot with real referees** until the "Before a pilot" items are done, and not ready for real credentials until Spartan has approved rules, content and a pass policy.

## Outcome (19 November 2026)

All the confirmed bugs and the UI "fix now" items are fixed (commit e895f2f), with tests for each. The pilot decisions:

- **A** Paid overage allowed: the database bills for use past the free allowance instead of pausing.
- **B** Application Insights, an API-failure alert and a £100 monthly budget alert.
- **C** The site uses the restricted `learn_app` login. (Firewall and SQL auditing left as they were.)
- **D** Download-my-data, admin export and erase are built; a draft notice and procedure are in [../learning/privacy-draft.md](../learning/privacy-draft.md) for Spartan to approve.
- **E** A nightly table backup (30 days), a restore script and [../runbook.md](../runbook.md). Blob soft delete not turned on.
- **F** Deploys stay manual, but must be committed, and `/version.json` records what's live.
- **G** Practice for everyone is the free in-browser camera; real practice servers are for head referees and admins.

## Confirmed bugs (fix now)

| # | What | Where |
|---|---|---|
| 1 | A learner can re-issue their own credential: withdraw from a completed programme, re-enrol, complete a lesson; old completions and the passed attempt still count, and a fresh credential is issued (renewing an expired one with no new assessment) | `programmes.js` enrol/withdraw, `lessons.js` checkCompletion, `assess.js` onComplete |

| 4 | Someone removed as a site admin keeps the learning platform's global admin role | `learn/index.js` who() |
| 5 | Narration can be generated for any voice name, by any member, without limit: a cost risk on Azure Speech | `lessons.js` narrationLink, `media.js` |
| 6 | The CSV export allows spreadsheet formula injection from display names, and loads every credential before filtering | `reports.js` exportCsv |
| 7 | A lesson done in a preview translation can't be done again once that translation is approved | `completion_once`, `lessons.js` complete |
| 8 | A learner left on a superseded version can't finish it or move to the new one | `programmes.js` getProgramme |
| 9 | Waking the paused database can take longer than a web request is allowed (45 s): the first visit after a quiet hour may fail, and the page doesn't retry | `db.js`, `core.js`, `learn/learn.js` |
| 10 | Viewing a rule page rebuilds all rule links each time, outside a transaction: slow, and two viewers at once can collide | `govern.js` syncLinks |

## Before a pilot with real referees (decisions and setup)

| # | What | Needs |
|---|---|---|
| A | The free SQL offer pauses the database for the rest of the month once its allowance (about 55 hour-long wakes) is used | your decision: allow paid overage, or a provisioned database (from about £4 a month) |
| B | No monitoring or alerts: errors only go to the function log | Application Insights and a budget alert (small cost) |
| C | The site connects to SQL as the server admin | a least-privilege database user (no cost) |
| D | Real referees' names and emails: no privacy notice, no delete or export procedure | Spartan's privacy decisions, then a notice and a procedure |
| E | Backups: Table Storage (referees, admins, assignments, bookings) has none; storage is locally redundant without soft delete | turn on soft delete and versioning; a simple export; a restore runbook |
| F | Deploys are manual from this PC with no record of what's live | a GitHub Actions deploy from `main`, with a smoke test |
| G | Practice cameras share the 5-server limit with events (and HeadJudge) | reserve capacity for events, or limit practice on event days |
